## Routing and guards
| Prefix | Allowed role | Unauthorised behaviour |
|---|---|---|
| `/`, `/services`, `/login`, `/register` | public | signed-in users redirected to `roleHome()` |
| `/portal/*` | customer (must have an account, else → `/portal/onboarding`) | redirect to own home |
| `/admin/*` | admin (+ MFA satisfied) | 404 |
| `/work/*` | worker, supervisor (`verify/*` supervisor only) | 404 |
`roleHome`: customer → `/portal`, admin → `/admin`, worker/supervisor → `/work`. Guards run in middleware (fast redirect) **and** in each area layout via `getUser()`; RLS remains the real enforcement.

## Data and mutation conventions
- **Reads**: Server Components with the user-JWT client; pagination via `range()`; no client-side secrets.
- **Writes**: Server Actions → zod parse → table insert (content) or RPC (status change) → `revalidatePath`; errors mapped by `lib/errors.ts`.
- **Uploads**: client → Storage with the user session (policy-checked) → then insert the metadata row; failures leave no DB row. Signed URLs for display.
- **Forms**: react-hook-form + zod + shadcn `Form`; every mutating button has pending/disabled state; destructive actions use `ConfirmDialog` and require a reason where the DB requires one.
- **Status display**: one `StatusBadge` + label map per enum so wording stays consistent across areas.

## UX principles
- Mobile-first: single-column, thumb-reachable primary action, 44px targets; worker area uses large buttons, bottom tab bar, camera-first flows.
- Customer sees one clear "what happens next" card per request (e.g. "Quotation ready – review and approve").
- Admin board is a work queue, not a report: each card is something someone must act on today.
- English first; copy structured for later Bahasa Malaysia (`next-intl`).
